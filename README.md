# Учебная платформа ORM

Веб-приложение для курса по JPA и Hibernate. Преподаватель ведёт курсы, публикует задания и тесты, проверяет решения. Студент записывается на курс, отправляет работу и просматривает результаты. Проверяющий работает через Swagger UI.

## Локальный запуск

Для запуска через Docker Compose нужны Docker, Compose и OpenSSL. Используйте локальный файл `.secret.demo` или воссоздайте его следующими переменными. Не добавляйте его в Git.

### Доступ к Docker в Linux

Команда `docker info` должна показывать сведения о сервере Docker без `sudo`. Если она сообщает `permission denied` для `/var/run/docker.sock`, добавьте текущего пользователя в группу `docker`:

```bash
getent group docker >/dev/null || sudo groupadd docker
sudo usermod -aG docker "$USER"
```

Выйдите из сеанса Linux и войдите заново, затем проверьте доступ командами `id -nG` и `docker info`. В списке групп должна появиться `docker`. Если нужно продолжить из текущего терминала, откройте оболочку с обновлёнными группами:

```bash
sudo -u "$USER" -- bash
id -nG
docker info
```

После проверки запускайте Docker Compose и Maven от своего пользователя. Доступ к Docker нужен и для запуска проекта через Compose, и для интеграционных тестов Testcontainers. Группа `docker` даёт привилегии уровня root. [Документация Docker](https://docs.docker.com/engine/install/linux-postinstall/)

### Переменные окружения

| Переменная | Значение |
| --- | --- |
| `DB_USER` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL |
| `DEMO_PASSWORD` | Пароль демонстрационных аккаунтов, от 8 символов до 72 байт |
| `JWT_PRIVATE_KEY` | Закрытый RSA-ключ в формате DER PKCS#8, закодированный в Base64 |
| `JWT_PUBLIC_KEY` | Открытый RSA-ключ в формате DER SubjectPublicKeyInfo, закодированный в Base64 |
| `DB_URL` | JDBC URL для запуска без Compose, например `jdbc:postgresql://localhost:5432/orm` |

Пример подготовки ключей. Команды выводят строки для настройки локального файла.

```bash
umask 077
key_dir=$(mktemp -d)
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out "$key_dir/private.pem"
printf 'JWT_PRIVATE_KEY='
openssl pkcs8 -topk8 -nocrypt -in "$key_dir/private.pem" -outform DER | openssl base64 -A
printf '\nJWT_PUBLIC_KEY='
openssl pkey -in "$key_dir/private.pem" -pubout -outform DER | openssl base64 -A
printf '\n'
rm -r "$key_dir"
```

```bash
chmod 600 .secret.demo
docker compose --env-file .secret.demo up --build
```

Для запуска без Compose нужны JDK 25, Maven 3.9 и доступный PostgreSQL с созданной базой. Передайте те же переменные окружения, включая `DB_URL`, и запустите:

```bash
mvn spring-boot:run
```

По умолчанию используется профиль `dev`. Он включает настройки `demo` для Swagger UI и начального наполнения базы. Hibernate обновляет схему при запуске. Compose публикует приложение только для локальных подключений. Пароль используется при создании демонстрационных аккаунтов в новой базе.

- `test` подключается к отдельной базе через `TEST_DB_URL`, `TEST_DB_USER` и `TEST_DB_PASSWORD`. Hibernate создаёт и удаляет схему, поэтому этот профиль предназначен для одноразовой базы. Отправка писем выключена.
- `prod` проверяет существующую схему и отключает Swagger UI. Для выбора профиля задайте `SPRING_PROFILES_ACTIVE=prod`.
- Существующие интеграционные тесты используют `demo` и передают настройки временной базы напрямую из Testcontainers.

## Демонстрация API

Откройте [Swagger UI](http://localhost:8080/swagger-ui/index.html). Контракт OpenAPI доступен в [JSON](http://localhost:8080/v3/api-docs). Вызовите `POST /api/auth/login` с одним из адресов и паролем `DEMO_PASSWORD`, скопируйте поле `accessToken` и вставьте его в **Authorize**. Токен действует 30 минут.

- `student@example.test` — просмотр курсов, запись, отправка решения и прохождение теста.
- `teacher@example.test` — управление своими курсами, просмотр участников, задания, оценивание и тесты.
- `admin@example.test` — управление пользователями и категориями.

1. Как студент откройте `GET /api/courses`, выберите «Основы Hibernate» и запросите его структуру по ID.
2. Возьмите ID урока и задание через `GET /api/lessons/{lessonId}/assignments`. Отправьте решение через `POST /api/assignments/{id}/submissions` с телом `{"work":"Описание решения"}`.
3. Авторизуйтесь как преподаватель и выставьте оценку через `PUT /api/submissions/{id}/grade`. Запрос с ролью студента вернёт `403`.
4. Снова авторизуйтесь как студент. Найдите тест через `GET /api/courses/{courseId}/quizzes`, откройте его по ID и отправьте ответы через `POST /api/quizzes/{id}/attempts`. В теле `{"answers":{"42":[101,102]}}` ключом служит ID вопроса, значением — список ID выбранных вариантов. Используйте ID из ответа API.
5. Выполните `DELETE /api/courses/{courseId}/enrollments/me` и затем `POST /api/courses/{courseId}/enrollments`. Система активирует ту же запись. Сданные работы и результаты тестов сохраняются.

При конфликте, например повторной сдаче задания или удалении объекта с сохранёнными результатами, API возвращает `409`.

## Аналитика и уведомления

- `GET /api/analytics/me` возвращает студенту его баллы по курсам и общий итог. В расчёт входят оценённые задания. После отписки история остаётся доступной.
- `GET /api/analytics/courses/{courseId}/ranking` возвращает преподавателю рейтинг активных студентов его курса. Место определяется долей набранных баллов. Равные результаты делят место, студенты без оценок идут в конце.
- `GET /api/analytics/quizzes/{quizId}/statistics` возвращает преподавателю число попыток и уникальных участников, средний, минимальный и максимальный процент. В статистику входят повторные попытки.

После сохранения нового задания уведомление получает каждый активный студент курса. После выставления или изменения оценки письмо получает автор работы. Приложение передаёт уведомления отправителю после успешной фиксации транзакции.

Реальная отправка по умолчанию выключена. Для подключения Resend задайте переменные `EMAIL_ENABLED=true`, `EMAIL_API_KEY` и `EMAIL_FROM` с разрешённым в Resend адресом. Сбой почтового провайдера записывается в журнал. Автоматических повторных отправок нет. В тестах используются записывающий отправитель и подставной HTTP-сервер.

## Структура и проверка

`web` принимает запросы и возвращает DTO. `service` задаёт границы транзакций и проверяет права на объекты. `repository` и `entity` управляют данными PostgreSQL. `security` выполняет аутентификацию. Open Session in View отключён. Коллекции загружаются по мере необходимости в транзакции сервиса.

Для тестов нужны JDK 25, Maven и доступный Docker:

```bash
mvn verify
```

На этапе `verify` Maven запускает Checkstyle для исходного кода и тестов. Та же команда выполняется в GitHub Actions при push и pull request. Проверка завершается ошибкой, если обнаружит пустой оператор, переопределение `equals` без `hashCode`, неявный переход между ветками `switch` или несовпадение имени внешнего типа с именем файла.

Чтобы запустить только статический анализ без Docker, выполните `mvn checkstyle:check`. Правила находятся в `config/checkstyle/checkstyle.xml`.

Testcontainers запускает отдельный PostgreSQL. Тесты проверяют схему, CRUD, связи и каскады, JWT, конкурентную запись на курс, сдачу и оценивание, результаты тестов и сохранение учебной истории. Отдельный тест обращается к незагруженной коллекции после завершения транзакции и проверяет `LazyInitializationException`. Затем тот же сценарий проверяет явно загруженный DTO. Тесты не используют БД демонстрационного профиля.
